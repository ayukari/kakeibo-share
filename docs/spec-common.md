# 共通仕様（Android・iOS で同じ）

両 OS のアプリはこの決まりに合わせる。計算と権限はサーバー（Supabase の DB 関数と RLS）が正しい値を持ち、アプリはそれを表示するだけにする。

## 権限

| できること | オーナー | 管理者 | メンバー | 閲覧のみ |
|---|---|---|---|---|
| 見る（グループに公開の記録・集計・精算） | ○ | ○ | ○ | ○ |
| 記録する・自分の記録を直す・消す | ○ | ○ | ○ | × |
| 他人の記録を直す・消す | ○ | ○ | × | × |
| 精算を記録する | ○ | ○ | ○ | × |
| 精算を確認する | ○ | ○ | 受け取った本人 | × |
| カテゴリ・予算・定期的な収支 | ○ | ○ | × | × |
| 招待・権限の変更・外す | ○ | ○（管理者は作れない） | × | × |
| 操作の履歴 | ○ | ○ | × | × |
| オーナーを渡す・家計簿の削除 | ○ | × | × | × |

「自分だけ」の記録は作った本人しか見えず、集計・精算に入らない。権限はアプリの表示でも分けるが、決めるのはサーバー（関数が `KB403` を返す）。

## お金と日付

- 金額は円の整数（1〜999,999,999）。小数・マイナスは入れられない。全角数字・カンマ・¥・円は入力で受け付ける。
- 日付は日本時間の日付（`YYYY-MM-DD`）。日時は UTC で保存し、表示で（UTC）と書く。
- 均等割り: `floor(金額 / 人数)` を全員に、余りは参加の早い順（参加日時 → ID）に 1 円ずつ。`tests/vectors/splits.json`。
- 差額 = 立て替え（割り勘の支出で払った額）− 負担 + 払った精算 − 受け取った精算（確認済みだけ）。`tests/vectors/settlement.json`。
- 精算の提案は確認待ちの分を差し引いて出す。記録できる金額は残りの差額まで（二重の精算を防ぐ）。
- 予算は始めた月から、次の予算で置き換えるまで続く。全体は支出の合計、1 人の予算はその人の負担で数える。

## 二重登録・同時編集

- 新しい記録には `client_request_id`（UUID）を付ける。通信が切れて送り直しても、サーバーは同じ記録を 1 件だけにする。
- 同じ日・同じ金額・同じカテゴリの記録があるときは、保存の前に「似た記録があります」と確かめる。
- 編集と削除は `version` を送る。ほかの人が先に直していたら `KB409`（読み直してもらう）。
- 定期的な収支は (定期の ID, 日付) が一意。アプリを開くたびに `generate_due_recurring` を呼んでも二重にならない。

## エラー

| サーバーのコード | 分類 | 画面の文 |
|---|---|---|
| KB401 / HTTP 401 | Unauthorized | ログインの期限が切れました |
| KB403 / 42501 / HTTP 403 | Forbidden | この操作をする権限がありません |
| KB404 | NotFound | 見つかりませんでした |
| KB409 | Conflict | ほかの人が先に変更しました |
| KB422 / 22P02 / 23514 | Validation | 項目ごとの文（`hint` が項目名） |
| 通信できない | Network | 通信できませんでした（保存はされていません） |
| それ以外 | Server | サーバーでエラーが起きました |

`tests/vectors/errors.json` で両 OS の分類が同じことを確かめる。

## オンライン前提

- 家計簿のデータは端末に保存しない（端末に残すのは、ログインのセッションと最後に開いた家計簿の ID だけ）。
- 通信できないときは保存ボタンを押してもエラーになり、入力は画面に残る。保存できたように見せない。
- セッションは Android Keystore（AES-GCM）/ iOS Keychain に保存する。Android は端末のバックアップからも除外している。iOS の Keychain の項目が暗号化バックアップで新しい端末へ移るかどうかは、supabase-swift の既定の設定のままで、まだ確かめていない（未テスト）。
